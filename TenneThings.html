Install Release

Bij het mergen van een wijzigng in GIT, wordt er automatisch een proces getriggered om een opleveringen naar Ontwikkel uit te voeren.

Voor een oplevereing naar Test, Acc of Prod (bijv. T12), moet er een release worden opgegeven (in JIRA, de sprintnaam) en via 'Build with parameters' de deployement gestart.

    Stappen:
  • Starts Jenkins
  • kies [applicatie]_Deployements > kies [applicatie]_Deploy_[omgeving] en start Build with parameters
  • Vul sprintnummer (vb. 202547) in en druk op Build. (Let op: bij de ene laatste stap blijft 't proces hangen. Klik erop en druk op proceed.')

  • Handmatige acties: Soms zijn er bij een Release handmatige acties, bijvoorbeeld een hotfix, waarbij een story handmatig moeten worden gezet in Productie.
    • Plaaats de inhoud van de hotfix (story-inhoud) in een deelmap (bijvoorbeeld Algemeen Q:\SRY ) op de VDI machine
    • Deze hotfix is dan bereikbaar vanuit de productie machine op schijf J (Data J:\Algemeen\SRY)
    • Voor de scripts direct op de juiste productie database uit.

  • Handmatige acties: Uitzetten van een publicatie.
    • Verwijder de Job van de desbetreffende publicatie in Delphi (bijv. ATR_01)
    • Zoek in tabel DQF_DEFINITIONS de desbetreffende prublicatie op
    • Zet de BVALIDITY_FROM in de toekomst, bijv. 01-01-2099
    • Zet de IND_ACTIVE_FILL en de IND_ACTIVE_CHECK op 'N'

UnInstall Release

Het terugdraaien van een story is voornamelijk een handmatige actie. Hierbij kunnen we 2 gevallen onderscheiden:
  1. Er is nog geen merge geweest met de DEV branch en de wijzigingen zijn niet deployed naar Test
    • Er is geen actie nodig in de DEV branch en ook niet in de Test omgeving
    • Check out de feature story branch
    • Als er wijzgingen zijn in de Release map, maak dan nieuw (voor de volgende sprint) map aan
    • Verplaatst (GIT) de wijzigingen naar de nieuwe map
    • Ruim bestanden en mappen op in de oude map (GIT) en commit de wijzigngen

  2. De wijzigingen zijn reeds gemerged en deployed naar Test
    • Draai de wijzigingen handmatig terug in Test, door de UnInstall scripts te draaien en voor ddl de vorige versie
    • Check out de DEV branch
    • Verwijder van de Release mappen de wijzingen
    • Plaats voor ddl-objecten de vorige versie terug. Een manier om de vorige versie terug te krijgen is om een compare
      uit te voeren en van daaruit het origineel op te slaan.
    • Commit de wijzigingen in de DEV branch. Voor de feature branch volg de acties uit stap 1.
    • Update de status van de story en geef een kort verslag in Comment

SQLcl

SQLcl willen we voornamelijk inzetten voor releasing en gecontroleerd uitvoeren van deploy- en rollback-scripts:

Verbinden database: sql -name <connectie_naam> (waarbij <connectie_naam> de naam van de connectie is zoals gedefinieerd in VS Code, bijv. AetherDev)
Deploy script draaien: @deploy.sql
Rollback script draaien: @rollback.sql
Logging starten: spool release_log.txt
Logging stoppen: spool off
Sessie verlaten: exit

Projectinrichting

Stappen voor het inrichten van een SQLcl-project:

  1. INIT: project init -name AvySRY -schemas AVY
  2. Maak een branch: !git checkout -b feature-1
  3. Export: project export [-o <objectnaam>]

Bouwproces

Stappen voor het bouwen en exporteren van een database-object:

  1. Bouw database object en verifieer het in de database.
  2. Voer stap 2 en 3 van Projectinrichting uit.
  3. Stage met command: Project stage. Dit voegt de wijziging door in /dist/next/change.
  4. Stage custom file met command: Project stage add-custom -file-name <filename>.
  5. Doe een commit en push in GIT.
  6. Genereer daarna het artifact met command: project gen-artifact -version next. Dit maakt in map artifact\avy_test-next.zip aan .
    1. Geef naam van de zip aan met -name <zipfilename>.
    2. Een commit is niet nodig bij artifact.

Deploy in Build en Test omgeving

Vervolgstappen na het bouwproces voor uitlevering en controle:

  1. Deploy naar de Build-omgeving.
    1. Ga naar de build-omgeving: sql.exe -name <buildomgeving connectstring>
    2. Deploy met: project deploy -file artifact\<zipfilename> -verbose
  2. Verify & test in de Test-omgeving.
    1. Ga naar de test-omgeving: sql.exe -name <testomgeving connectstring>
    2. Deploy met: project deploy -file artifact\<zipfilename> -verbose
  3. Merge de wijzigingen na een succesvolle controle.

Voorbeeld releaseproces

Een eenvoudig releaseproces met SQLcl kan er als volgt uitzien:

  1. Open SQLcl en maak verbinding met de juiste omgeving, bijvoorbeeld Test of Acceptatie.
  2. Start logging zodat je achteraf precies ziet wat is uitgevoerd.
  3. Voer het deploy-script uit.
  4. Controleer of het script zonder fouten is afgerond.
  5. Stop de logging en sluit de sessie af.
  6. Als de release teruggedraaid moet worden, voer je daarna het rollback-script uit.

Voorbeeld:

sql -name AetherDev
spool release_20260319.log
@deploy.sql
spool off
exit

Als het deploy-script fouten geeft, leg je de uitkomst vast in de log en kun je indien nodig daarna @rollback.sql uitvoeren.
